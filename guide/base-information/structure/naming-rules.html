네이밍 규칙

Capitalization​

Casing Styles​

아래 표기 형식을 사용하며, 식별자별로 구분해서 사용해요.

StyleDescription
lowercase모든 단어를 띄어쓰기 없이 소문자로 표기해요.
lower_case_with_underscores모든 단어를 소문자로 표기하고, 단어 사이에 _를 삽입해요.
UPPERCASE모든 단어를 띄어쓰기 없이 대문자로 표기해요.
UPPER_CASE_WITH_UNDERSCORES모든 단어를 대문자로 표기하고, 단어 사이에 _를 삽입해요.
lowerCamelCase첫 글자를 소문자로, 나머지 단어의 첫 글자는 대문자로 표기해요.
UpperCamelCase첫 글자를 대문자로, 나머지 단어의 첫 글자도 대문자로 표기해요.
Capitalized_Words_With_Underscores각 단어의 첫 글자를 대문자로 표기하고, 단어 사이에 _를 삽입해요.

Style for Identifiers​

추가적인 세부 규칙은 각 항목에서 다루며, 기본 규칙은 아래와 같아요.

IdentifierStyleExample
VariablelowerCamelCase, lowercase$fooBar, $i
ClassUpperCamelCaseFooBar
NamespaceUpperCamelCaseFooBar
PropertylowerCamelCase$fooBar
MethodlowerCamelCasefooBar
ConstantUPPER_CASE_WITH_UNDERSCORESFOO_BAR
Internal Functionlower_case_with_underscoremysql_query
Databaselower_case_with_underscores, UPPER_CASE_WITH_UNDERSCORESgd_goods, USP_GET_GD_GOODS_LIST
Columnlower_case_with_underscoresgoods_name

Filenames​

PHP​

클래스명과 파일명이 같아야 해요.

Resources​

  • Image: lower_case_with_underscores를 사용하되, 구분자는 _ 대신 .을 사용해도 돼요.
  • CSS: lower_case_with_underscores를 사용하되, 구분자는 _ 대신 .을 사용해도 돼요.
  • JS: lower_case_with_underscores를 사용하되, 구분자는 _ 대신 .을 사용해도 돼요.

General​

Word Choice​

  • 의미가 전달될 수 있도록 쉽고 간단한 단어를 사용해요.
  • 흔히 쓰이는 용어(예: email, XML, file, error 등)를 사용할 경우 반드시 1개 이상의 수식어를 함께 사용해요.
  • 헝가리안 표기를 사용하지 않아요.
  • Control Structures에 i, j, k, v 등의 네이밍을 사용하는 것은 복잡한 중첩 구조가 아닌 경우에는 허용돼요.

Abbreviations​

  • 약속된 약어 외에는 단어를 모두 풀어 써요.

Namespaces & Classes​

  • UpperCamelCase 형태로 표기해요.
  • Interface는 접미사로 Interface를 붙여요.
  • Trait는 접미사로 Trait를 붙여요.
  • Abstract 클래스는 접두사로 Abstract를 붙여요.
  • Exception 클래스는 접두사로 Exception을 붙여요.

Methods​

  • lowerCamelCase 형태로 표기해요.
  • 동사로 시작해요.
  • Visibility를 반드시 지정해요.
  • private method일 경우에만 _로 시작해요.

Properties​

  • lowerCamelCase 형태로 표기해요.
  • 명사로 시작해요.
  • Visibility를 반드시 지정해요.
  • private method일 경우에만 _로 시작해요.

Constants​

  • UPPER_CASE_WITH_UNDERSCORES 형태로 표기해요.
  • true, false, null은 소문자를 유지해요.

Internal Functions​

  • 내장 함수는 모두 소문자와 _로 표기해요.
  • PHP 코드와 프로젝트 코드를 구분하기 위해 반드시 gd_를 prefix로 붙여요.

Databases​

Table Name Prefix​

  • 프로젝트별 구분을 위해 Table Name Prefix를 사용할 수 있어요.
  • 고도몰의 Table Name Prefix는 es_예요.

Tables​

  • lower_case_with_underscores 형태로 표기해요.
  • DBMS 내장 키워드명, 함수명을 사용하지 않아요.
  • 의미 없는 단어나 약속되지 않은 약어를 사용하지 않아요.

Columns​

  • lower_case_with_underscores 형태로 표기해요.
  • DBMS 내장 키워드명, 함수명을 사용하지 않아요.
  • 의미 없는 단어나 약속되지 않은 약어를 사용하지 않아요.

Indexes​

  • lower_case_with_underscores 형태로 표기해요.
  • 인덱스에 포함된 모든 컬럼명을 입력해요.
  • 인덱스 형태별로 아래의 prefix를 사용해요.
    • Unique: uidx
    • Index: idx
