PHP8 업그레이드 사전준비 가이드

구버전 PHP를 사용하는 상점을 PHP 8로 업그레이드하기 전에 확인할 사항을 안내합니다.

개발 언어 자체의 세세한 변경점은 PHP 공식 매뉴얼을 참고하세요.

이 문서는 고도몰에서 달라진 특징과, 상점이 사전에 준비할 항목만 다룹니다.

이 문서를 처음 열었다면 먼저 확인하세요

아래 '섹션별 확인 포인트' 표의 담당 구분을 먼저 보세요.

  • 개발자 개발 담당자가 처리합니다. 운영자는 완료 여부만 확인하면 됩니다.
  • 협업 운영자가 해당 여부를 확인하고, 실제 조치는 개발 담당자와 함께 진행합니다.
  • 운영자 운영자가 관리자 화면에서 직접 확인하고 조치할 수 있습니다.

소스를 튜닝(커스터마이징)한 상점이라면 담당이 '개발자'인 항목을 개발 담당자에게 전달하세요.

기본 상태로 사용 중이라면 8번, 그리고 6·7·9번을 우선 확인하세요.

섹션별 확인 포인트​

섹션담당우리 상점 확인 포인트
1. 엄격한 타입 관리개발자소스를 튜닝한 적이 있으면 개발 담당자에게 전달
2. 암호화 모듈개발자직접 만든 암호화 로직이 있으면 개발 담당자 점검
3. 0으로 나누기 방지개발자소스를 튜닝한 적이 있으면 개발 담당자에게 전달
4. 외부 PHP 라이브러리개발자직접 설치한 외부 라이브러리가 있으면 호환 확인
5. 소스 튜닝 정리개발자튜닝 파일이 있으면 개발 담당자가 정리·점검
6. DB 커스터마이징협업커스텀 테이블이나 백업 테이블을 쓰는지 확인
7. 상품 등록/수정 화면협업상품 등록 화면을 개선 화면으로 쓸지 결정
8. 이미지/CDN운영자상세설명에 절대경로 이미지를 넣은 적이 있는지 확인
9. 주문 개선 플래그협업정기결제·선물하기 등 신규 주문 기능 사용 여부

1. 엄격한 타입 관리 개발자​

운영자 요약

PHP 8은 데이터를 더 엄격하게 다룹니다.

예전에는 "숫자처럼 보이는 텍스트"를 숫자로 취급해도 경고만 나왔지만, PHP 8에서는 오류가 나면서 실행이 멈춥니다.

고도몰이 호환용 임시 함수를 넣어 두었으므로 대부분의 상점은 바로 문제가 되지 않습니다.

다만 소스를 튜닝한 상점은 튜닝한 부분을 개발 담당자가 점검해야 합니다.

이 항목은 운영자가 직접 조치할 것이 없습니다.

이전 버전에서는 숫자가 아닌 값을 숫자처럼 계산하면 경고(Warning)만 발생했습니다.

PHP
count('2'); // 문자열 "2"를 count()에 넣음
  • 이전 버전: 경고만 발생하고 실행은 계속됨
  • PHP 8: 경고가 아니라 오류가 발생하여 실행이 멈춤

고도몰에서는 기존 소스에 느슨한 타입 체크(특히 널, 배열)를 위반하는 문법이 많이 허용돼 왔습니다.

엄격한 타입 체크로 전환할 때의 사이드이펙트를 막기 위해 gd_count()라는 자체 함수가 임시로 적용되어 있습니다.

PHP
// PHP 8 호환을 위해 변경됨
gd_count('2'); // 안전하게 동작
경고

원본 소스의 잘못된 부분을 점차 수정하면서, gd_count()는 다시 PHP 기본 함수(count())로 되돌릴 예정입니다.

즉, 현재 임시 함수(gd_count)가 쓰이는 곳이 있지만 해당 함수는 deprecate될 예정입니다.

튜닝 시 데이터 타입을 고려하여 개발하고, gd_ 함수를 새로 사용하지 않습니다.

2. 암호화 모듈 개발자​

운영자 요약

기존 암호화 방식(Mcrypt)이 PHP에서 완전히 사라졌습니다.

고도몰 기본 기능은 다른 방식(openSSL)으로 이미 교체되어 있습니다.

결제, 로그인 등과 관련해 직접 만든 암호화 로직이 있는 상점만 개발 담당자의 점검이 필요합니다.

잘못 다루면 기존에 암호화한 데이터를 다시 읽지 못할 수 있으므로, 이 항목은 개발 담당자가 처리해야 합니다.

Mcrypt 모듈이 더 이상 지원되지 않습니다.

DEPRECATED as of PHP 7.1.0 and REMOVED as of PHP 7.2.0

모든 Mcrypt 암호화는 openSSL 등 다른 암호화 알고리즘을 사용하도록 변경되었습니다.

mcrypt → openssl 교체 작업 예시 코드
PHP
<?php
function encrypt($plaintext, $secret_key)
{
$key = hash('sha256', $secret_key, true);
$iv = random_bytes(openssl_cipher_iv_length('AES-256-CBC'));
 
$encrypted = openssl_encrypt(
$plaintext,
'AES-256-CBC',
$key,
OPENSSL_RAW_DATA,
$iv
);
 
return base64_encode($iv . $encrypted);
}
 
function decrypt($ciphertext_base64, $secret_key)
{
$key = hash('sha256', $secret_key, true);
$data = base64_decode($ciphertext_base64);
$iv_length = openssl_cipher_iv_length('AES-256-CBC');
 
$iv = substr($data, 0, $iv_length);
$ciphertext = substr($data, $iv_length);
 
$decrypted = openssl_decrypt(
$ciphertext,
'AES-256-CBC',
$key,
OPENSSL_RAW_DATA,
$iv
);
 
return $decrypted;
}
 
// 사용 예시
$secret = 'my-secret-key';
$plain = 'Hello World';
 
$enc = encrypt($plain, $secret);
$dec = decrypt($enc, $secret);
 
echo "ENC: $enc\n";
echo "DEC: $dec\n";

3. 0으로 나누기 방지 (안전 나누기) 개발자​

운영자 요약

전환율이나 평균처럼 나눗셈으로 계산하는 지표에서, 나누는 값이 0이면 PHP 8은 오류를 냅니다.

화면이 멈추거나 오류가 노출될 수 있는 문제입니다.

고도몰은 이를 막는 헬퍼를 제공하며, 튜닝 소스에서 나눗셈을 직접 다룬 상점만 개발 담당자가 이 헬퍼를 적용하면 됩니다.

이 항목은 운영자가 직접 조치할 것이 없습니다.

PHP 8에서는 나누기 연산에서 분모(나누는 값)가 0이면 즉시 오류가 발생합니다.

쇼핑몰 지표(전환율, 평균값 등)를 계산할 때 분모가 0이 될 수 있어, 화면이 멈추거나 오류가 노출될 위험이 있습니다.

이 문제를 막기 위해 고도몰은 다음 헬퍼를 제공합니다.

PHP
use Framework\Utility\NumberUtils;
/*
* 나누기 연산 시 피제수에 0을 주입할 경우 발생하는 division by zero 오류 방어
* @param mixed $dividend 피제수
* @param mixed $divisor 제수
* @param null|string $returnZeroType 0으로 강제 리턴될 경우 지정한 타입으로 강제 형변환
* @return float|int $quotient 몫
*/
NumberUtils::divisionExceptZero($numerator, $denominator, $fallback = 0, $scale = null);

4. 외부 PHP 라이브러리 호환성 확인 개발자​

운영자 요약

상점에 직접 설치한 외부 PHP 라이브러리가 있다면, PHP 8에서도 동작하는지 확인이 필요합니다.

직접 설치한 라이브러리가 없다면 이 항목은 해당되지 않습니다.

확인과 업데이트는 개발 담당자가 진행합니다.

상점에 직접 설치한 외부 PHP 라이브러리가 있다면 PHP 8 호환 여부를 확인하고 필요 시 업데이트해 주세요.

직접 설치한 라이브러리는 각 공식 저장소에서 PHP 8 지원 버전을 확인해 주세요.

5. 소스 튜닝 관련 확인 개발자​

운영자 요약

불필요한 튜닝 파일이 많으면 이전 작업 시간이 늘고 오류 가능성이 높아집니다.

또한 PHP 8에서 새로 예약어가 된 단어를 클래스명이나 함수명으로 쓰고 있으면 오류가 납니다.

두 가지 모두 코드를 읽고 판단해야 하므로 개발 담당자가 처리합니다.

이 항목은 운영자가 직접 조치할 것이 없습니다.

의미 없는 튜닝 파일 정리​

불필요한 튜닝 파일이 많을수록 이전 작업 시간이 늘어나고 오류 가능성이 높아집니다.

아래 기준에 해당하는 파일은 사전에 제거해 주세요.

유형설명예시
빈 클래스상속만 받고 추가 정의가 없는 파일class MyOrder extends GdOrder {} (본문 없음)
빈 생성자parent::__construct() 호출만 있는 파일function __construct() { parent::__construct(); }
빈 컨트롤러parent::index() 호출만 있는 파일function index() { parent::index(); }
복붙 파일원본 소스와 내용이 완전히 동일한 파일diff 결과가 없는 튜닝 파일

상점 튜닝 경로

구분경로
관리자 스킨{상점}/admin/*
고도몰 로직{상점}/module/*

PHP8 예약어 충돌 확인​

PHP 8에서 새롭게 예약어로 지정된 단어를 클래스명이나 함수명으로 사용하고 있다면 수동으로 변경해야 합니다.

충돌 대상 예약어

TEXT
match / enum / readonly / never / fn / final

수정 예시

PHP
// 충돌: 'match'는 PHP8 예약어
class match {
public function fn() { ... }
}
 
// 수정: 예약어와 겹치지 않는 이름으로 변경
class MatchHandler {
public function processFilter() { ... }
}

6. DB 커스터마이징 관련 확인 협업​

운영자 요약

직접 만든 커스텀 테이블이나 백업 테이블이 새 환경(MySQL 8)과 맞지 않으면, 이전 후 주문과 클레임 처리에서 오류가 날 수 있습니다.

특히 백업 테이블에 컬럼이 빠지면, 이전 후 취소·교환·반품 처리 시 해당 데이터를 찾지 못해 오류가 발생합니다.

이 항목은 개발 담당자가 업그레이드 전에 점검해야 합니다.

운영자는 아래 접기에서 우리 상점이 해당하는지만 먼저 확인하세요.

우리 상점이 해당하는지 확인하는 법 (운영자용)

다음 중 하나라도 해당하면 개발 담당자에게 DB 점검을 요청하세요.

  • 기술팀에 DB 수정을 의뢰한 적이 있다
  • 주문 테이블에 우리 상점만 쓰는 항목(컬럼)이 있다
  • 이름이 Original로 끝나는 백업용 테이블을 쓰고 있다

PK 없는 커스텀 테이블​

직접 생성한 커스텀 테이블에 Primary Key(PK)가 없으면 MySQL 8 이전 시 DDL 오류가 발생합니다.

이전 전에 해당 테이블에 PK를 추가해 주세요.

SQL
-- PK 없는 테이블 확인
SELECT TABLE_NAME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = '{your_db_name}'
AND TABLE_NAME NOT IN (
SELECT TABLE_NAME
FROM information_schema.TABLE_CONSTRAINTS
WHERE CONSTRAINT_TYPE = 'PRIMARY KEY'
AND TABLE_SCHEMA = '{your_db_name}'
);
 
-- PK 추가 (예시)
ALTER TABLE 커스텀_테이블명 ADD PRIMARY KEY (id);

MyISAM 엔진 사용 테이블​

MySQL 8 환경에서는 MyISAM 엔진을 사용할 수 없습니다.

직접 생성한 커스텀 테이블 중 MyISAM을 사용하는 경우 업그레이드 전에 InnoDB로 변경해 주세요.

SQL
-- MyISAM 테이블 확인
SELECT TABLE_NAME, ENGINE
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = '{your_db_name}'
AND ENGINE = 'MyISAM';
 
-- InnoDB로 변경
ALTER TABLE 테이블명 ENGINE = InnoDB;

백업 테이블 컬럼 동기화​

원본 테이블(예: es_order, es_orderHandle)에 컬럼을 추가했다면, 백업 테이블(es_*Original)에도 동일하게 컬럼을 반영해 주세요.

동기화가 누락되면 이전 후 취소·교환·반품 등 클레임 처리 시 오류가 발생합니다.

동기화 누락 시 발생 문제 예시

TEXT
원본 테이블: es_order (컬럼 A, B, C, D 추가됨)
백업 테이블: es_orderOriginal (컬럼 A만 반영됨)
→ 이전 후 취소/교환/반품 처리 시 "Unknown column 'B'" 오류 발생

컬럼 추가 예시

SQL
-- 원본에 추가한 컬럼을 백업 테이블에도 동일하게 반영
ALTER TABLE es_orderOriginal
ADD COLUMN custom VARCHAR(255) DEFAULT '' AFTER order_id;
운영자 체크리스트
  • 개발 담당자에게 DB 점검 요청 (이 항목이 필수임을 명시)
  • 업그레이드 전 DB 백업 재확인
  • 마이그레이션 후 주문 및 클레임 처리 테스트

7. 상품 등록/수정 관련 확인 협업​

운영자 요약

상품 등록 화면은 기존 화면과 개선 화면 두 가지가 있습니다.

개선 화면은 옵션과 재고를 한 화면에서 함께 입력할 수 있어 편리합니다.

화면 전환은 관리자 설정으로 가능하지만, 기존 화면을 직접 튜닝한 상점은 이전 후 오류가 날 수 있어 개발 담당자의 확인이 필요합니다.

두 화면의 차이 운영자​

기존 화면(goods_register.php)은 옵션 탭과 재고 탭이 분리되어 있습니다.

옵션을 설정한 뒤 별도 탭으로 이동해 재고를 입력합니다.

개선 화면(goods_register_option_stock.php)은 옵션과 재고가 한 탭에 통합되어 있습니다.

옵션을 설정하면서 재고 수량을 같은 화면에서 바로 입력할 수 있습니다.

권장 사항

기존 화면을 직접 튜닝해 쓰는 상점은 이전 후 상품 등록·수정에서 오류가 날 수 있습니다.

개선 화면으로의 전환을 권장하며, 전환 전후로 상품 등록·수정 테스트를 진행하세요.

사용 중인 화면 확인 개발자​

SQL
SELECT * FROM es_config WHERE groupCode = 'goods' AND code = 'option_1903';
쿼리 결과사용 중인 화면
결과 없음 또는 {"use": "n"}goods_register.php (기존 화면)
{"use": "y"}goods_register_option_stock.php (개선 화면)

기존 화면(goods_register.php) 튜닝 상점 주의

해당 파일을 튜닝한 경우 이전 전후로 별도 QA와 수정이 필요합니다.

개선 화면(goods_register_option_stock.php)으로의 변경을 권장합니다.

개선 화면으로 전환

SQL
INSERT INTO es_config VALUES ('goods','option_1903','{\"use\": \"y\"}',now(),NULL);

8. 이미지/CDN 관련 확인 운영자​

운영자 요약

상품 상세 설명을 HTML 탭으로 직접 편집하면서 이미지 주소를 전체 주소(절대경로)로 넣은 경우, 업그레이드 후 이미지가 깨질 수 있습니다.

이 항목은 운영자가 관리자 화면 편집기에서 직접 확인하고 수정할 수 있습니다.

수정 대상이 많으면 개발 담당자에게 일괄 변경을 요청하는 편이 빠릅니다.

Proplus 서버를 쓰는 상점은 이 항목을 확인하지 않아도 됩니다.

Proplus 서버의 경우 해당 사항은 별도 확인하지 않으셔도 됩니다.

왜 문제가 되나요?​

고도몰은 서버 환경에 따라 CDN 도메인이 다릅니다.

환경CDN URL 형식예시
Pro 서버IP가 포함된 CDN 서비스 도메인https://cdn-pro-web-250-211.cdn-nhncommerce.com/...
Proplus 서버업체 실제 도메인 기반 URLhttps://my-shop-domain.com/...

서버 환경에 따라 CDN 도메인이 달라지므로, HTML 탭에서 전체 주소(절대경로)로 입력한 이미지는 업그레이드 이후 깨질 수 있습니다.

미리 점검해 주세요.

확인 방법​

상품 상세 설명 데이터에 전체 CDN 주소가 포함된 경우가 있는지 DB에서 확인합니다.

SQL
-- 상품 상세 설명에 절대 CDN URL이 포함된 상품 확인
SELECT *
FROM es_goods
WHERE goodsDescription LIKE '%https://cdn%'
OR goodsDescription LIKE '%http://cdn%';

해당 데이터가 있으면 전체 주소를 상대 주소로 수정해 주세요.

HTML
<!-- 전체 주소: 이전 후 도메인이 바뀌면 깨짐 -->
<img src="https://cdn-pro-web-123-456.cdn-nhncommerce.com/my_shop/goods/detail.jpg">
 
<!-- 상대 주소: 환경에 관계없이 정상 작동 -->
<img src="/goods/detail.jpg">

9. 주문 개선 플래그 확인 협업​

운영자 요약

정기결제, 선물하기 같은 신규 주문 기능은 주문 개선이 적용된 상점에서만 동작합니다.

적용 여부는 관리자 화면에서 확인하고 전환할 수 있습니다.

주문 관련 소스를 튜닝한 상점은 전환 전에 개발 담당자와 함께 점검해야 충돌을 피할 수 있습니다.

주문 개선(신주문, OrderNew) 구조는 PHP 7과 8 공통으로 적용되어 있습니다.

다만 GODO26 버전에서 추가된 신규 주문 기능(정기결제, 선물하기 등)은 이 OrderNew 기준으로 처리되므로, 해당 기능을 쓰려면 상점이 주문 개선이 적용된 상태여야 합니다.

적용 상태 확인과 전환 운영자​

이미 적용된 상점은 추가 조치가 필요 없습니다.

아직 적용 전이면 아래 순서로 전환합니다.

  1. 관리자 기본설정 ▸ 주문 정책 ▸ 주문 기본 설정으로 이동합니다. (최고운영자 기준)
  2. 주문 개선(업그레이드) 적용 상태를 확인합니다.
  3. 화면이 자동으로 점검한 안내를 확인한 뒤 주문 업그레이드 적용을 실행합니다.

전환 시 주문 개선이 적용되고, 이후 신규 주문 기능을 사용할 수 있습니다.

전환 전 주의

주문 관련 소스를 튜닝한 상점은 신주문 구조와 충돌할 수 있습니다.

관리자 화면이 튜닝 파일 존재 여부를 자동으로 점검해 안내하므로, 안내가 나오면 개발 담당자와 함께 확인한 뒤 전환하세요.

플래그와 점검 대상 개발자​

상점별 적용 여부 플래그

  • 파일: config/orderNew.php → {"flag":"T"} / {"flag":"F"}
플래그상태GODO26 신규 주문 기능(정기결제·선물하기 등)
F주문 개선 적용 전 (레거시)사용 불가
T주문 개선 적용 완료정상 사용

전환 동작

관리자 화면에서 주문 업그레이드를 적용하면 config/orderNew.php가 {"flag":"T"}로 기록되고, 주문 정책(order.upgrade)도 T로 저장되어 이후 신주문(OrderNew) 로직이 적용됩니다.

전환 전 점검 대상 튜닝 파일

다음 파일이 module/ 하위에 튜닝되어 있으면 신주문(OrderNew) 구조와 충돌할 수 있어 사전 점검이 필요합니다.

업그레이드 전 최종 체크리스트​

업그레이드를 신청하기 전에 아래 항목을 담당별로 확인하세요.

개발 담당자에게 전달·확인 (소스를 튜닝한 상점)

  • (1) 타입 관련 튜닝 소스 점검, gd_ 함수를 새로 쓰지 않음
  • (2) 튜닝 소스의 Mcrypt 사용 여부 확인, openSSL 등으로 교체
  • (3) 튜닝 소스의 나눗셈 로직에 0으로 나누기 방어 적용
  • (4) 직접 설치한 외부 PHP 라이브러리의 PHP 8 호환 확인·업데이트
  • (5) 불필요한 튜닝 파일 정리, PHP 8 예약어(match/enum/readonly/never/fn/final) 충돌 확인

운영자와 개발 담당자가 함께 확인

  • (6) 커스텀 테이블 PK 추가, MyISAM을 InnoDB로 전환, 백업 테이블(es_*Original) 컬럼 동기화
  • (7) 현재 상품 등록 화면(기존/개선) 확인, 기존 화면을 튜닝한 상점은 QA와 전환 검토
  • (9) 신규 주문 기능을 쓰려면 주문 개선 적용 상태 확인, 주문 소스를 튜닝한 상점은 충돌 점검

운영자가 직접 확인

  • (8) 상품 상세설명의 절대경로 이미지 확인·상대경로 수정 (Proplus 서버는 제외)
